## DEC-01 — Application architecture alignment (resolved; database choice superseded by DEC-02)

- **Status:** Resolved by the user on 2026-10-31.
- **Decision:** Retain the existing Next.js + Prisma architecture. Do not migrate to Base44. The initial decision also retained PostgreSQL; DEC-02 later supersedes that database choice with SQLite.
- **Rationale:** The checkout already contains working App Router pages/handlers/actions, server-side services, GitHub/Octokit retrieval, Gemini, Prisma models/migrations, NextAuth, Vercel KV, chat, reports and security scanning. Replacing those foundations would add migration risk and unnecessary rewrite work.
- **Consequences:** New endpoints use Next.js Route Handlers/server actions; deterministic analysis belongs in modular, injectable `src/lib/services/` code; persistence uses Prisma; existing APIs and workflows are preserved wherever practical; secrets remain server-side; no second backend is introduced. `ChatRun` remains a chat-run record, not an analysis job. Existing generated Mermaid stays distinct from an evidence-derived graph.
- **Security follow-up:** `src/lib/auth.config.ts` currently copies OAuth `access_token` into the returned session. Phase 5 must remove browser exposure and keep any needed credential server-side.
- **Acceptance:** The architecture guidance and five phases consistently match this stack, and `docs/decisions.md` records the decision. No feature code is changed to resolve DEC-01.

## DEC-02 — Switch the Prisma database to SQLite

The user explicitly requested SQLite instead of PostgreSQL so the application can run locally without a database server. The schema, active migration path, local startup scripts, environment example and docs now use SQLite. PostgreSQL migrations remain archived and no PostgreSQL data was migrated. SQLite requires persistent writable storage; the current Vercel deployment is not supported by this local-file database setup. See `docs/decisions.md` for consequences and verification.
